# AI agent skills

Most new UI will be written with an AI coding agent. Agent skills are instructions an agent loads on demand (Claude
Code reads them from `.claude/skills/`), and these teach it to work **with** the design system instead of
around it: which components exist, which tokens to use, how to check its work, and how to extend the system.

This page is generated from the skill files in the repo, so it always matches what agents actually read.

## For product teams

<>{skills.filter((s) => s.audience === 'product').map((s) => <SkillCard key={s.name} skill={s} />)}</>

**How to get them.** Apps created with `npm create @latitudelabs` (or `pnpm new` locally) already have them: the app's
`postinstall` runs `latitude-skills`, which copies these skills from the installed design-system package into
`.claude/skills/`. Every `npm install` or design-system update refreshes them, so agents always know about the
latest components. In an existing app, add this to `package.json`:

```json
"scripts": { "postinstall": "latitude-skills" }
```

**Run the audit yourself** (no agent needed), e.g. before opening a PR:

```bash
node .claude/skills/latitude-ui-review/scripts/audit.mjs src
```

## For design system maintainers

<>{skills.filter((s) => s.audience === 'maintainer').map((s) => <SkillCard key={s.name} skill={s} />)}</>

These live in this repository's `.claude/skills/` and load automatically for anyone working on the design system
with Claude Code.

## Writing or changing a skill

- Product skills: `packages/design-system/skills/<name>/` (shipped with the package; name must start with
  `latitude-` to be synced). Maintainer skills: `.claude/skills/<name>/`.
- The frontmatter `description` decides when an agent uses the skill, so say what it does **and** when to use it.
- When you add a component, update `latitude-ui`'s catalog and `references/components.md`. That's how agents learn
  it exists (the `ds-add-component` skill includes this step).
